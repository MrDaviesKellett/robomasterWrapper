# Post-release learner UX completion report

Released baseline: 0.9.0. Package version remains 0.9.0; no version section, tag, push, or publish was created. Changes are committed locally for Martin's review.

## Findings

1. **Silent connect — fixed.** Immediate flushed progress output names the normalized connection type and SDK route. Heartbeats appear every ten seconds during blocking initialization and retries. `RoboMaster(connect_timeout=5)` bounds the overall connection wait, including retry delays. Default `None` preserves existing SDK retry timing. Invalid nonfinite or nonpositive timeouts are rejected (minimum supported timeout: 0.001 seconds).
   - Start template: `Connecting to robot via {connection} on {target} ...`
   - Default AP line: `Connecting to robot via ap on 192.168.2.1 ...`
   - Heartbeat template: `Still connecting to robot via {connection} on {target} ... ({elapsed:.0f} seconds elapsed)`
   - Targets use configured AP/USB addresses; station mode uses `ROBOT_IP_STR` when configured, otherwise `network discovery` or `network discovery (serial {serial})`.
   - Failure text retained: `Robot could not be connected. Check power, network mode, and serial number.`
   - SDK exceptions retain the suffix ` Last error: {error}`.
   - Timeout example: `Robot could not be connected. Check power, network mode, and serial number. Last error: connect_timeout of 5 seconds expired.`
   - Additional timeout validation text: `connect_timeout must be finite.` Numeric type/range errors use the common validators.
   - Limitation: SDK `initialize()` exposes no cancellation hook. On timeout the constructor returns an error immediately, stops further retries, and closes any late SDK connection after the in-flight call returns. It cannot interrupt that underlying SDK call mid-flight. This is documented in the API reference.
2. **No-argument move — fixed.** Omitted coordinates raise before sending a command. Explicit zero coordinates, including `move(x=0, y=0)`, retain the existing SDK move behavior. Supplying only speed or blocking options also raises.
   - Exact ValueError: `move() requires x, y, or angle. Accepted arguments: x, y, angle, speed, turn_speed, blocking, timeout. Use move(x=0, y=0) for an intentional stop.`
3. **Validator wording — fixed.** Shared validators now consistently name the parameter and accepted Python types. Integer-only APIs retain their integer restriction. Clamp validates each parameter before comparing bounds.
   - Numeric template: `{name} must be of type int or float.`
   - Integer template: `{name} must be of type int.`
   - RGB tuple template: `{name} must be of type tuple with three int values (r, g, b).`
   - Examples: `x must be of type int or float.` (chassis); `x must be of type int.` (arm); `rgb[1] must be of type int.` (RGB element).
   - Clamp names `val`, `min_val`, or `max_val` individually with the numeric template. No existing tests asserted the replaced type-error text.
4. **UART guidance — fixed.** Exact NotImplementedError: `UART receive is unavailable: the upstream SDK receive path crashes on send ACKs. Use send() for output; receive stays unavailable until the upstream SDK is fixed.` Sending remains available.
5. **README requirement — fixed.** First line: `**Python 3.14+ required.** Earlier Python versions cannot install robowrap.`

`CHANGELOG.md` has an Unreleased section covering all five findings. The API reference documents connection timing and explicit movement arguments.
